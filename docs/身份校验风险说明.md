# 新 API 身份校验缺失 — 风险说明（一页版）

> 面向：项目经理 / 需求方
> 编写：前端
> 日期：2026-10-17
> 结论先行：**正常使用没有问题；但任何懂 F12 的人都能看到其他客户的数据。**

---

## 一、问题是什么（一句话）

新 API 不校验"这个请求是谁发的"。用户 Id 由前端在请求里传，**改成别人的 Id 就变成别人**。

---

## 二、实测证据（可复现）

以下请求**没有登录、没有 cookie、没有 token**，用 Postman 直接发出：

```
POST /api/customerByUser
{"UserId": 1}
```

**实际返回：**

```json
{"code":"SUCCESS","message":"OK","data":[
  {"Id":1,"Company":"洪昌泥井有限公司","SN":"2026091614470963462","Manager":"王某某",...}
]}
```

再把 `UserId` 换成别的一直加下去，凡是有数据的都会返回。

另外：

```
POST /api/customer   {}
→ 同样返回全部客户（管理员接口也一样无校验）

POST /api/userLogin  {"UserName":"admin","Password":"任意"}
→ 响应头里没有 Set-Cookie（没有建立会话）
```

---

## 三、这意味着什么

| 场景 | 结果 |
|---|---|
| 客户 A 正常使用 | 正常，只能看到自己的数据 |
| 客户 A 按 F12 把 `UserId` 改成 1002 | **能看到客户 B 的全部数据**（工地 / 警报 / 照片） |
| 写个脚本从 1 跑到 1000 | **能拿完所有客户的数据** |

---

## 四、为什么现在挡不住

旧后台（`_Layout.cshtml`）里有这段，是正确的：

```csharp
Session["loginUserId"] = data.Id;   // 存在服务器上，客户端改不了
```

但**新的 `/api/*` 接口里没有这段逻辑** —— 它从请求体里读 `UserId`。

判断依据很直接：**如果后端真的从 Session 取 Id，那 `UserId` 这个请求参数根本不应该存在。** 而文档里写着它「必须传」。

---

## 五、怎么改（后端，约半天）

所有 `/api/*` 接口统一：

1. 进入先检查会话，没有 → 返回 401
2. 用户 Id **从服务端会话取**
3. **忽略**请求体里的 `UserId`

> 若新 API 无 Session 环境，最低成本替代：
> 登录时生成随机 `UserToken` 存库并返回前端；之后请求带这个串，后端反查用户。
> 关键点：**不能让前端传"用户编号"**，必须是猜不到的随机串。

**前端配合**：只需把 `UserId` 参数去掉，改动约 30 分钟。

---

## 六、如何决定（给管理层的选项）

| 选项 | 说明 | 代价 |
|---|---|---|
| **A. 现在修** | 后端加会话校验，前端配合改动 | 后端半天 + 前端 30 分钟 |
| **B. 上线后修** | 先交付，第二个版本补 | 上线期间存在越权风险 |
| **C. 维持现状** | 接受风险 | 需书面确认，出事由业务方承担 |

**前端建议 A。** 改动量小，且这是客户数据隔离问题——写进合同里的东西。

---

## 七、需要确认的一句话

> 请确认：新 API 是否接受「用户 Id 由前端传入、后端不做校验」这一现状。
>
> - 若接受 → 请在验收文档中注明，后续因此产生的数据可见问题不由前端承担
> - 若不接受 → 请按第五节改造，前端会在半天内配合完成
