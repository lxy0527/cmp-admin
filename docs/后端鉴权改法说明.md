# 后端鉴权改法说明（可直接转给后端）

> 2026-10-21 · 前端侧整理
> 目的：把「管理接口不校验 token」这一条收敛成**一个统一入口**的改法，不是逐个接口手写。

---

## 一句话

**在源头上加一个统一的校验口子，让所有 `/api/*` 都经过它**，而不是给每个接口各写一遍判断。

---

## 现状（可复现）

只带 `ApiId` / `ApiKey`，**不带** `Authorization`，直接打：

```bash
curl -X POST http://192.168.77.15:82/api/customer \
  -H "Content-Type: application/json" \
  -H "ApiId: <ApiId>" -H "ApiKey: <ApiKey>" \
  -d '{}'
```

现在返回：`{"code":"SUCCESS","data":[{"Company":"洪昌泥井有限公司","Manager":"王某某","Tele":"123456",...}]}`

同样情况适用于 `/api/alarm`、`/api/album`、`/api/user`。

**对照**（已经做对的）：`/api/customerByUser` 不带 token 返回 `{"code":"FAIL","message":"token不能为空"}`。

---

## 目标（三条验收）

1. `POST /api/customer` 不带 `Authorization` → **401**（且不返回任何业务数据）
2. 带**普通账号**（`Role=0`）的 token 打 `/api/customer` → **403**
3. 带**管理员**（`Role=1`）的 token → **200 + 数据**（现有功能不受影响）

---

## 推荐实现：统一中间件（ASP.NET Core）

```csharp
// Program.cs —— 放在 app.UseRouting() 之后、app.MapControllers() 之前
app.Use(async (ctx, next) =>
{
    var path = ctx.Request.Path.Value ?? "";

    // ① 白名单：不需要登录就能访问
    var whitelist = new[]
    {
        "/api/userLogin",
        "/api/userRegister",
        "/api/email",           // 发验证码
        "/api/changePassword",
        "/api/verifyEmail",
        "/api/verifyUserName"
    };
    if (whitelist.Any(w => path.StartsWith(w, StringComparison.OrdinalIgnoreCase)))
    {
        await next();
        return;
    }

    // ② 只拦 /api/*，其它（静态文件、MVC 页面）不管
    if (!path.StartsWith("/api/", StringComparison.OrdinalIgnoreCase))
    {
        await next();
        return;
    }

    // ③ 取 token
    var auth = ctx.Request.Headers["Authorization"].ToString();
    var token = auth.StartsWith("Bearer ", StringComparison.OrdinalIgnoreCase)
        ? auth.Substring(7).Trim()
        : "";

    if (string.IsNullOrWhiteSpace(token))
    {
        await WriteJson(ctx, 401, "token不能为空");
        return;
    }

    // ④ 反查用户（复用 byUser 那套现成逻辑）
    var user = GetUserByToken(token);   // ← 后端已有
    if (user == null)
    {
        await WriteJson(ctx, 401, "token无效或已过期");
        return;
    }

    // ⑤ 判管理权限
    var isAdminPath = path is "/api/alarm" or "/api/album" or "/api/customer" or "/api/user"
                   || path.StartsWith("/api/alarm") || path.StartsWith("/api/album")
                   || path.StartsWith("/api/customer") || path.StartsWith("/api/user");
    // 注意：上面这组要排除 *ByUser —— 普通账号要能用 byUser
    var isByUserPath = path.EndsWith("ByUser", StringComparison.OrdinalIgnoreCase);

    if (isAdminPath && !isByUserPath && user.Role != 1)
    {
        await WriteJson(ctx, 403, "没有管理员权限");
        return;
    }

    // ⑥ 把用户挂到上下文，后面的接口直接取，不用再解析
    ctx.Items["UserId"] = user.Id;
    ctx.Items["Role"]   = user.Role;

    await next();
});

static async Task WriteJson(HttpContext ctx, int status, string message)
{
    ctx.Response.StatusCode = status;
    ctx.Response.ContentType = "application/json; charset=utf-8";
    await ctx.Response.WriteAsync($"{{\"code\":\"FAIL\",\"message\":\"{message}\",\"data\":\"\"}}");
}
```

**改动量**：一个中间件 + 一段白名单。**一处代码覆盖全部 48 个接口**，以后新加的接口自动受保护。

## 如果觉得中间件重，就用 ActionFilter

```csharp
public class RequireTokenAttribute : ActionFilterAttribute
{
    public int MinRole { get; set; } = 0;

    public override void OnActionExecuting(ActionExecutingContext ctx)
    {
        var token = (ctx.HttpContext.Request.Headers["Authorization"].ToString() ?? "").Replace("Bearer ", "").Trim();
        var user = GetUserByToken(token);              // 现成逻辑

        if (string.IsNullOrWhiteSpace(token)) { ctx.Result = Fail(401, "token不能为空"); return; }
        if (user == null)                     { ctx.Result = Fail(401, "token无效"); return; }
        if (user.Role < MinRole)              { ctx.Result = Fail(403, "没有管理员权限"); return; }

        ctx.HttpContext.Items["UserId"] = user.Id;
    }
}
```

挂载方式（一个控制器一行，而不是一个接口一行）：

```csharp
[RequireToken]
public class CustomerController : ControllerBase { ... }

[RequireToken(MinRole = 1)]
public class AdminController : ControllerBase { ... }
```

## 两个顺带解决的细节

1. **别再 302 跳 `/Account/Login`** —— API 里用 `401` / `403` + JSON。
   302 会被浏览器/axios 自动跟走，落点又是一个 HTML 页面，前端只能靠"拿到 HTML"间接判断，很脆弱。
   > 这一条是建议，不是前置条件 —— 前端已经把 302 当"无权限"处理了，能用。

2. **不要读请求体里的 `UserId`** —— 一律从 token 反查。
   现在 byUser 已经是这么做的（传 `UserId=999999` 也查不到别人的数据），把这个习惯推广到所有接口。

---

## 前端不需要改

登录后所有请求**已经自动带** `Authorization: Bearer <token>`
（见 `src/api/request.ts` 请求拦截器），管理接口也一直在带上，只是后端目前没读。

**后端改完，前端一行都不用动。**

## 验收命令（后端自测）

```bash
# 1) 不带 token → 期望 401
curl -i -X POST http://192.168.77.15:82/api/customer \
  -H "Content-Type: application/json" \
  -H "ApiId: <ApiId>" -H "ApiKey: <ApiKey>" \
  -d '{}'

# 2) 普通账号 token → 期望 403
curl -i -X POST http://192.168.77.15:82/api/customer \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <user01 的 token>" \
  -H "ApiId: <ApiId>" -H "ApiKey: <ApiKey>" \
  -d '{}'

# 3) 管理员 token → 期望 200 + 数据
curl -i -X POST http://192.168.77.15:82/api/customer \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <admin 的 token>" \
  -H "ApiId: <ApiId>" -H "ApiKey: <ApiKey>" \
  -d '{}'
```

三条结果一致即可视为完成。

## 风险背景（为什么值得做）

| 当前缓解 | 一旦上公网 |
|---|---|
| 需要 `ApiId` / `ApiKey` | 密钥一旦泄露，全库敞开 |
| 后端目前仅内网可达 | 公网路由可达，任何人都能打 |

数据包含：客户公司名、负责人姓名、联系电话、账号邮箱/电话/工号。
**这两条缓解都不是"鉴权"，只是"暂时没人知道地址"。**
