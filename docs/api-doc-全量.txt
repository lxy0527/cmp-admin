##### index.html  【通用部分】
CMP系统api文档
港进建机CMP接口文档 I-VISION-CMP-API
通用说明：
请求方式：GET / POST / PUT / DELETE
请求格式：application/json
响应格式：application/json
数据处理：请求和响应json数据都要做encode处理，避免特殊字符错乱。
字符编码：UTF-8
头部参数：所有接口必须传参数：ApiId和ApiKey，防止黑客攻击系统，防止无效请求增加服务器负载。
开放域名：正式上线域名必须录入数据库才有权限请求，防止黑客攻击系统，防止无效请求增加服务器负载。。
传输协议：测试是用http方便，正式上线强制https （强制https后账号密码可不用再次加密传送）
状态编号：StatusCode 成功：200（http200只代表通信成功） 失败：400 未授权：401
返回编码：code 成功：SUCCESS 错误：FAIL
具体描述：message 成功：OK ，其它情况具体验证描述
接口地址：接口域名/path （path为具体的根地址，接口都放在api文件夹下，示例：接口域名/api/user）
命名规则：数据库字段使用驼峰命名规则，如：UserName （部分因为缩写或便于阅读例外）。
请求头部示例：
-H ContentType:"application/json; charset=UTF-8";
-H "ApiId", value;
-H "ApiKey", value;
Method:"POST";
curl 接口域名/path
请求body示例： 美观输出
{"Id":1001,"UserName":"admin"}
成功响应示例： 美观输出
{"code":"SUCCESS","message":"OK","data":""}
错误响应示例： 美观输出
{"code":"FAIL","message":"错误描述","data":""}
备注：以上是所有接口都有的通用部分，下面的文档不在介绍此部分内容。

##### WebSocket.html  【WebSocket通用】
CMP系统api文档
港进建机CMP接口文档 I-VISION-CMP-API
WebSocket通用说明：
数据格式：json
数据处理：json数据都要做Encode处理
字符编码：UTF-8
鉴权参数：所有接口必须传参数：ApiId和ApiKey，防止黑客攻击系统，防止无效请求增加服务器负载。示例：wss://接口域名/path?ApiId=xxx&ApiKey=xxx
开放域名：正式上线域名必须录入数据库才有权限请求，防止黑客攻击系统，防止无效请求增加服务器负载。
传输协议：测试是用ws://方便，正式上线强制wss:// （强制wss://后账号密码可不用再次加密传送）
状态编号：状态 成功：101 失败：400 未授权：401
返回编码：code 成功：SUCCESS 错误：FAIL
具体描述：message 成功：OK ，其它情况具体验证描述
接口地址：wss://接口域名/path （path为具体的根地址，接口都放在api文件夹下，示例：wss://接口域名/api/alarmWebsocket）
命名规则：数据库字段使用驼峰命名规则，如：UserName （部分因为缩写或便于阅读例外）。
握手（连接）示例：
wss://接口域名/api/alarmWebsocket?ApiId=xxx&ApiKey=xxx
握手成功或失败返回：
握手成功 HTTP 状态 101，握手失败，不返回业务数据。
客户端发心跳示例： 美观输出
{"Type":"ping","Timestamp": 1728700000000}
心跳成功服务器端回复示例： 美观输出
{"Type":"pong","Timestamp": 1728700000000}
备注：心跳失败判断Type不等于pong即可，心跳失败一般情况是连接断开了，或者网络卡顿，这些情况也无法返回自定义数据。这种情况需等几秒（一般为5秒，主要看服务器和当时网络流畅度）看收到没有，几秒后没收到就需要客户端再次主动重新连接。
服务器端推送示例： 美观输出
{ "Type": "alarm","code": "SUCCESS", "data": { "Id": 1, "SN": "1001" } }
客户端回应
推送成功立即向服务器端回应，避免重复发起推送。
推送成功客户端回应示例： 美观输出
{"Type":"ack","code":"SUCCESS"}
备注：以上是所有WebSocket接口都有的通用部分，下面的文档不在介绍此部分内容。
